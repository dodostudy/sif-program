SIF 데이터 갱신 방법

공단(KOSHA)이 산업재해 고위험요인(SIF) 아카이브를 다시 배포하면, 새 엑셀 한 장을 받아 사이트 데이터로 바꾸는 절차입니다. 명령 한 줄로 전 과정이 돌아가고, 사람이 정해야 하는 것만 목록으로 돌려줍니다.

대상 SIF 위험성평가 지원시스템 기준 배포판 2026-04-01 (3,459건) 작성 2026-09-10

한눈에 보기

공단 엑셀아카이브(건설업) 시트
▶
A단계28열 확장 · 규칙 적용
▶
하위유형·대표사례군집 · medoid
▶
db.json마스킹 · 검증 · 사이트 데이터

이 문서로 할 수 있는 것 — 새 배포판 엑셀을 source/에 넣고 명령 한 줄을 실행하면 data/db.json이 새로 만들어집니다. 규칙으로 정하지 못한 항목은 scripts/out/미결_*.csv로 나옵니다. 그것만 사람이 채우고 다시 실행하면 됩니다.

지금 배포판(2026-04, 3,459건)으로 이 절차를 그대로 돌리면 현재 사이트의 db.json과 바이트 단위로 같은 파일이 나오는 것을 확인했습니다. 즉, 새 배포판에서 달라지는 것은 오직 데이터 차이뿐입니다.

0

준비 — 한 번만

파이썬 3.9 이상과 패키지 네 개가 필요합니다. 터미널에서 프로젝트 폴더로 이동한 뒤:

pip3 install pandas numpy openpyxl scipy scikit-learn

이미 설치돼 있으면 "Requirement already satisfied"만 나오고 끝납니다. (사이트 확인용 로컬 서버는 파이썬에 내장돼 있어 따로 설치할 것이 없습니다.)

1

공단 엑셀을 source/에 넣기

공공데이터포털에서 받은 파일을 그대로 source/ 폴더에 둡니다. 파일 이름은 자유롭지만 날짜가 들어 있으면 나중에 알아보기 좋습니다.

  • 시트가 세 장(개요 / 아카이브(제조업등) / 아카이브(건설업))입니다. 스크립트는 이름에 "건설"이 들어간 시트를 자동으로 고릅니다. 시트 이름이 바뀌었으면 --sheet "시트이름"으로 지정합니다.
  • 열 순서는 연번 · 공종 · 작업명 · 단위작업명 · 재해종류 · 재해개요 · 기인물 · 재해유발요인 · 위험성 감소대책의 9열이어야 합니다. 열이 바뀌면 A단계가 "연번 헤더를 찾지 못했습니다"로 멈춥니다.
  • 원본 파일은 절대 고치지 않습니다. 마스킹·치환은 모두 산출물에서만 일어납니다.
2

명령 한 줄 실행

# 프로젝트 폴더에서
python3 scripts/build_all.py --xlsx "source/한국산업안전보건공단_산업재해 고위험요인(SIF) 아카이브_20270401.xlsx"

세 단계가 차례로 돌아갑니다. 보통 1~2분 걸립니다(하위유형 군집 계산이 대부분).

3

미결이 나오면 — 사람이 정하는 것

A단계는 규칙으로 정할 수 없는 항목을 만나면 산출물을 쓰지 않고 멈춥니다. 화면에 이렇게 나옵니다.

[3/4] 미결 점검
  ✗ 기인물 2건 → scripts/out/미결_기인물.csv
  ✗ 재해형태 5건 → scripts/out/미결_재해형태.csv

  미결 7건 — 산출물을 기록하지 않았습니다.

각 CSV의 조치 열에 무엇을 하면 되는지 적혀 있습니다. 종류별 처리 방법:

미결 파일뜻어디를 고치나
미결_기인물.csv공단이 새 기인물 명칭을 썼다. 어느 분류인지, 12대 기인물인지 모른다. 이름만 바뀐 것이면 scripts/mapping/giinmul-crosswalk.json의 alias에 "새 이름": "기존 이름" 추가.
진짜 새 항목이면 giinmul-lookup.json의 항목에 추가.
미결_재해형태.csv재해종류가 전도·화상·파열인데 원문에서 기전을 자동으로 못 읽었다. 재해개요를 읽고 재해형태를 정한 뒤 scripts/mapping/jaehae-manual.json의 항목에 추가. 키는 CSV의 지문 열 값을 그대로 씁니다.
미결_재해종류.csv공단이 새 재해종류 용어를 썼다. scripts/mapping/jaehae-term.json의 TERM_FIX(1:1 치환) 또는 KEEP(같은 표기)에 추가.
미결_발생월.csv재해개요에서 연·월을 못 읽었다(표기가 특이함). 대개 소수라 그대로 둬도 됩니다(발생월 없음으로 처리). 많으면 build_stage_a.py의 MP 정규식 보강.
미결_코드.csv공종·작업명·단위작업명에 번호 접두("1.1.1")가 없다. 공단 원본 표기 확인. 실제로 번호가 없으면 그대로 둡니다.

매핑 파일에 항목을 추가하는 예

기인물 룩업 — 새 기인물 "방음벽 자재"가 나왔고, 분류는 '자재', 12대 기인물이 아니라면:

"방음벽 자재": {
  "기인물분류": "자재",
  "12대기인물": false,
  "위험도순위": null,
  "3년간사고비중": "해당없음"
}

재해형태 개별판정 — 미결_재해형태.csv의 지문이 덤프트럭이성토사면아래로전도되어운전자가...이고 원문을 읽어 '깔림 뒤집힘'으로 정했다면:

"덤프트럭이성토사면아래로전도되어운전자가...": {
  "재해형태": "깔림 뒤집힘",
  "재해종류": "전도",
  "사유": "덤프트럭이 성토사면 아래로 전도, 운전자 사망"
}

왜 id가 아니라 지문인가 — 공단은 배포판마다 연번을 다시 매깁니다. id로 적어 두면 다음 배포판에서 엉뚱한 사례에 붙습니다. 지문은 재해개요에서 공백·마스킹 기호·숫자를 뺀 앞 40자라, 연번이 바뀌어도 같은 사례를 다시 찾습니다.

매핑을 보완했으면 2단계 명령을 다시 실행합니다. 미결이 0이 될 때까지 반복합니다. 급하면 --allow-pending을 붙여 끝까지 돌릴 수 있는데, 이때 미결 재해형태는 공단 원문값(전도·화상·파열)이 그대로 남습니다.

4

결과 확인

  • scripts/out/갱신_리포트.md — 건수 변화가 상식적인가(보통 수백 건 증가). 새로 생긴 기인물·공종·재해형태가 있는가.
  • scripts/out/build_report.md — "금지 패턴 잔존 0건"인가. 대표사례가 하위유형마다 1건인가.
  • scripts/out/pii_audit.csv — 마스킹된 곳을 훑어본다. 실명·주소가 아닌데 지워진 것(과잉)이나, 남아 있는 고유명사(누락)가 있으면 build_dataset.py의 PII_RULES/PII_OVERRIDES에 반영.
  • 사이트를 로컬에서 열어 본다: 
    python3 -m http.server 8099
# 브라우저에서 http://localhost:8099/ — 대시보드 총 건수, 드롭다운, 추락높이 분석·발생시기 분석 탭

마스킹이 부족해 B단계가 멈추면(빌드 중단 — 금지 패턴 N건 잔존) 화면에 어떤 문장이 걸렸는지 나옵니다. 그 문장에 맞는 치환을 PII_OVERRIDES에 한 줄 추가하고 다시 실행합니다.

사람이 판단해야 하는 것 — 정리

  • 새 기인물의 분류와 12대 여부 (미결_기인물). 공단 명칭만 바뀐 것인지, 정말 새 항목인지.
  • 전도·화상·파열 사례의 재해형태 (미결_재해형태). 원문을 읽고 사람이 떨어졌는지, 깔렸는지, 넘어졌는지 정한다.
  • 개인정보 마스킹 결과 검수 (pii_audit.csv). 규칙은 이전 배포판 기준이라 새 문장에서 빠지는 것이 있을 수 있다.
  • 발전소(KOEN) 공정 규칙 — 새 공종이 생기면 scripts/mapping/koen-rule.json의 제외 목록을 볼 것. 현재는 교량공사·하천 및 항만공사·양수발전용 댐만 제외.
  • 하위유형 이름 (T4의 하위유형명) — 비어 있어도 사이트는 돌아간다. 붙이고 싶으면 Phase 5 항목.

자주 묻는 것

같은 엑셀로 다시 돌리면 결과가 똑같이 나오나요?

예. 군집은 random_state=0으로 고정돼 있고, 대표사례가 동률이면 id가 작은 쪽을 고르므로 같은 입력이면 같은 출력입니다. 2026-04판으로 검증했습니다.

공단이 기인물 이름을 또 바꾸면?

giinmul-crosswalk.json의 alias에 "새 이름": "기존 이름"을 넣으면 룩업이 기존 이름으로 이어집니다. 2026-04판에서 실제로 바뀐 14종은 같은 파일의 history에 기록돼 있습니다.

재해형태 판정은 어떤 순서로 되나요?

① 공단 재해종류를 1:1 치환(추락→떨어짐 등, TERM_FIX) ② 전도·화상·파열은 재해개요의 결과절에서 기전어(깔려·떨어져·맞아…)와 원인어(감전·폭발·화재…)를 읽어 자동 배정 ③ 그래도 안 되면 jaehae-manual.json의 개별판정 ④ 없으면 미결. scripts/out/재해형태_원문판독_검토목록.csv에 전도·화상·파열 전건의 배정 근거가 남습니다.

대표사례가 이전과 달라졌는데 괜찮나요?

새 사례가 들어오면 군집 경계가 움직이므로 일부 대표사례가 바뀌는 것이 정상입니다. 하위유형은 기인물×재해형태 칸 안에서만 나뉘므로 칸 건수가 100·30을 넘나들 때 하위유형 개수(5·3·1)도 바뀔 수 있습니다.

스크립트를 하나씩 따로 돌릴 수도 있나요? 
python3 scripts/build_stage_a.py --xlsx "source/원본.xlsx" [--out source/SIF_확장열.json] [--allow-pending]
python3 scripts/build_tables.py  --src source/SIF_확장열_3800건.json
python3 scripts/build_dataset.py --src source/SIF_확장열_3800건.json

build_dataset.py는 인수 없이 실행하면 현재 기본 경로(2026-04판)를 씁니다.

이전 데이터로 되돌리려면?

git checkout -- data/ source/로 커밋 전 상태로 돌아갑니다. 커밋 뒤라면 scripts/out/db_previous.json을 data/db.json으로 복사하거나 이전 커밋으로 되돌립니다.
