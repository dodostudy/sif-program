# 공공기관 개발 결과보고서 작성 프롬프트

## 사용법
아래 프롬프트를 복사한 뒤, `[대괄호]` 항목을 실제 내용으로 채워서 Claude에게 전달

---

## 프롬프트

```
다음 정보를 바탕으로 공공기관 제출용 개발 결과보고서를 작성해줘.

--- 기본 정보 ---
시스템명: [예: SIF 건설재해 위험성평가 지원시스템]
개발 주체: [예: 행복+ 분당발전본부 안전관리실]
보고 대상: [예: 본부 안전부서 임원 / 발주처 담당자]
보고 연월: [예: 2026. 04.]
배포 URL: [예: https://dodostudy.github.io/sif-program/]

--- 개발 배경 ---
문제 상황: [어떤 불편·공백이 있었는지]
해결 실마리: [어떤 데이터나 방법을 발견했는지]
개발 경위: [어떤 단계를 거쳐 만들었는지, 자체개발인지 외주인지]

--- 시스템 소개 ---
핵심 기능: [주요 기능 3~5가지]
사용 대상: [누가 쓰는지]
데이터 규모/출처: [어떤 데이터를 얼마나 쓰는지]
기술 방식: [어떤 기술로 만들었는지, 서버 유무, 비용 구조]

--- 차별점 ---
기존 방식 대비 달라진 점: [before → after 형태로]
특별히 강조할 기술/기능: [텍스트마이닝, 필터, 자동화 등]

--- 기대효과 ---
즉각적 효과: [현재 이미 나타난 변화]
확산 계획: [향후 어떻게 발전·공유할 것인지]

---

작성 조건:
1. 공공기관 보고서 형식 — 로마자 목차(Ⅰ, Ⅱ, Ⅲ…), 항목 앞 ○ 기호 사용
2. 문장 끝은 마침표 대신 "~추진", "~활용", "~기여", "~확산", "~마련" 등 공문 어체로 통일
3. 앞부분(개요~배경)은 마케팅 브로셔처럼 — 핵심 문구를 인용문(>) 또는 굵게 강조
4. before/after 비교가 필요한 부분은 코드블록 표 형식으로 시각화
5. 개발자(담당자) 본인이 자체 개발했음을 자연스럽게 강조
6. 마지막 종합 섹션은 3줄 이내 압축 요약 + ○ 항목 2~3개로 마무리
7. 전체 분량은 A4 1~2장 분량 (마크다운 기준 약 150~250줄)
```

---

## 잘 나오는 팁

**임팩트 있는 인용문 만들기**  
시스템의 핵심 가치를 한 줄 문장으로 만들어 `>` 인용문으로 넣을 것  
→ 예: `"2,574건의 실제 재해 데이터를, 누구나 5초 안에 꺼내 쓸 수 있게"`

**before/after 비교 코드블록**  
기존 방식과 신규 방식의 차이를 코드블록 안에 나란히 배치하면 한눈에 임팩트 전달  
→ 예: `서버 구축 필요 VS GitHub Pages 정적 배포`

**개발 경위는 STEP 화살표 흐름으로**  
```
STEP 1  데이터 확보
        ↓
STEP 2  구조화 · 가공
        ↓
STEP 3  개발 · 테스트
        ↓
STEP 4  배포 완료
```

**공문 어체 어미 예시**  
| 일반 문장 | 공문 어체 |
|-----------|-----------|
| ~개발했다 | ~자체 개발·배포 완료 |
| ~할 예정이다 | ~확산 추진 |
| ~에 도움이 된다 | ~역량 강화에 기여 |
| ~를 늘릴 것이다 | ~지속 확대 추진 |
| ~를 만들었다 | ~구축·운영 중 |
