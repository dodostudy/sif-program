## Context — 왜 만드는가

- **문제:** 전체 위험 구조를 **heat로 한눈에 조망**하고, 공정·기인물·재해유형을 **자유롭게 넘나들며(hop)** 파고들 수 있는 **통합 진입점**이 없다. 기존 페이지는 각 축을 따로 필터링하는 도구라, 축을 오가는 탐색과 전체 조망을 못 한다.
- **개념:** 상단 **3축 탭(공정 / 기인물 / 재해유형)** → 각 축의 **heat 랭킹 리스트(흰→빨강)** → 항목 선택 시 **상세 패널**에 다른 두 축 분포 + 사례 → 상세 속 항목을 누르면 **그게 새 포커스**가 되어 계속 파고듦(브레드크럼으로 경로 표시) → 끝까지 누르면 **개별 사고사망 사례**가 리프.
- **데이터 소스(확정):** db.json 동적 집계(정·역방향 그룹핑). `dropdown-ref.json` hierarchy는 공정 축의 계층 드릴에 사용.
- **기존 3페이지와 공존(확정):** 위험지도 = **조망 + 빠른 상호탐색**. 공정조회·기인물조회·재해형태분석 = **정밀 필터·전건 테이블·다운로드** 도구로 유지. → 위험지도의 상세 패널은 **요약(Top 차트 + 대표 사례)** 수준으로 가볍게, "전체 사례·필터"는 해당 기존 페이지로 **딥링크**. 세 페이지를 재구현하지 않는다.

> ⚠️ **데이터 캐비앗:** db.json에 사망/중상 구분 필드 없음 → 건수는 **"사망·중상 건수"**로 표기.

## 상단 — 3축 탭 + 브레드크럼

- **탭:** `[공정] [기인물] [재해유형]` — 진입 축 선택
- **브레드크럼(hop 경로):** `마감공사 › 비계 › 떨어짐 › 사례` — 각 단계 클릭 시 그 지점으로 복귀

## 각 탭 = heat 랭킹 리스트 (흰→빨강)

| 탭 | 리스트 | 계층/드릴 |
|---|---|---|
| **공정** | 공종 12개 heat 리스트 | [+]로 작업명(49)→단위작업명(113) 드릴 (`dropdown-ref` hierarchy) |
| **기인물** | 기인물 57개 heat 리스트 (12대 배지) | 단일 레벨, 건수 desc |
| **재해유형** | 재해형태 20개 heat 리스트 | 단일 레벨, 건수 desc |

- 각 행: `명칭 · heat 막대 · 건수 (전체%)`. 건수 내림차순.

## 상세 패널 — 선택 항목의 "다른 두 축 + 사례"

| 선택 축 | 상세 패널 구성 |
|---|---|
| **공정** 선택 | [재해유형 분포 도넛] · [기인물 Top 바] · [대표 사례 N건] |
| **기인물** 선택 | [재해유형 분포 도넛] · [발생 공정 바] · [대표 사례 N건] |
| **재해유형** 선택 | [발생 공정 바] · [기인물 Top 바] · [대표 사례 N건] |

- 상세 내부 분포 %는 **선택 스코프 대비**(리스트의 전체%와 구분).
- **사례 클릭 → 개별 사고사망 사례 카드**: 재해개요 · 재해유발요인 · 위험성감소대책 (+ 엑셀/인쇄)
- 상세 하단 **"전체 사례·필터 →"** 딥링크: 해당 스코프를 걸고 공정조회/기인물조회/재해형태분석으로 이동(공존 원칙).

## 상호이동(hop) 규칙

- 상세 속 항목(기인물 바·재해유형 도넛 조각 등) 클릭 = **새 포커스**. 탭이 해당 축으로 자동 전환, 브레드크럼 누적.
- 예: 공정'마감공사' → 상세의 기인물'비계' 클릭 → 기인물 탭 '비계' 포커스 → 상세의 재해유형'떨어짐' 클릭 → 재해유형 탭 '떨어짐' 포커스 …

## 집계 로직 (한글 canonical 값으로 집계, 표시만 tCat)

1. `DataLoader.loadDB()` + `loadDropdownRef()`
2. 현재 포커스 스코프로 `filterDB` → `aggregateBy(다른 축)` → `topN`
3. **리스트 건수·heat = 전체(2,574) 대비.** 상세 패널 분포 % = 선택 스코프 내 비중.
4. 정·역방향 모두 그룹핑으로 계산 (기인물→공정, 재해형태→공정 등 역방향 데이터 문제 없음)

## 색 규칙 (흰→빨강 sequential) — 확정

- **저위험=흰색 → 고위험=진한 빨강** 단일 계열. 건수 기준. 적록색맹 안전.
- ⚠️ 테마 대응: 다크 테마에선 저위험 끝을 **테마 표면색**으로 매핑(라이트=흰색→빨강 / 다크=어두운 표면→빨강). `CHART_COLORS.heatmapColor`를 흰↔빨강 램프로 조정하거나 헬퍼 1개 추가.

## 모바일 (필수 고려)

- 탭: 상단 세그먼트(필요 시 가로 스크롤), 행 높이 ≥44px(터치)
- 리스트 탭 → 상세 **전체폭 전환** + `←` 뒤로 / 브레드크럼으로 복귀
- 차트: 세로 1열 풀폭 / 데스크톱: 좌(리스트)+우(상세) 2단
- 사례 카드: 세로 스택, 텍스트 전문 표시

## i18n (버튼으로 영어 전환 — 기존 구조 그대로)

- 탭 라벨·축 명칭·브레드크럼·차트/리스트 라벨 → `I18n.tCat` / `t`
- 신규 UI 문구 → `ui_en.json`(한글 원문 키) → `translateDOM` 자동
- 동적 문구(건수·비중) → `${I18n.cases(n)}` / `isEn`
- `glossary_en.json` 미번역 기인물분류 5건 추가(고소작업대·기타가설구조물·말비계·이동식비계·기타자재)
- 사이드바 NAV 라벨 i18n / 최종 배선·감사는 **sif-i18n-keeper**

## 구현 순서 (Phase)

1. **Phase 1** — 페이지 골격 + 3축 탭 + 각 축 **heat 랭킹 리스트**(전체%·흰→빨강)
2. **Phase 2** — 상세 패널(선택 축의 다른 두 축 차트 + 대표 사례)
3. **Phase 3** — **hop**(상세 항목 클릭 → 포커스 전환) + **브레드크럼**
4. **Phase 4** — 공정 탭 계층 드릴(작업명·단위작업명) + 사례 카드 + 엑셀/인쇄 + 기존 페이지 딥링크
5. **Phase 5** — i18n 배선(sif-i18n-keeper) + 사이드바 등록
6. **Phase 6** — 모바일 반응형 마감 + 검증(sif-qa-verifier) + 배포

## 검증 (sif-qa-verifier)

- `node --check js/*.js`, JSON 파싱, `python3 scripts/i18n_audit.py` → 미커버 0
- **데이터 정합:** 각 축 리스트 건수 합 = 2,574 / 공종 건수 = 대시보드 수치
- 로컬서버 + 헤드리스 크롬 KO/EN 스크린샷(데스크톱/모바일)
- 회귀: 탭 전환, hop→포커스 전환, 브레드크럼 복귀, 사례 카드, 엑셀, 딥링크, 테마·언어 localStorage 유지

## 후속(별도 로드맵, 이번 범위 외)
